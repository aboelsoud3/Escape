# The missing piece: **Agent Memory Graph (AMG)**

This is the feature I haven't seen implemented well in most agentic coding systems, and it's the one I'd add if I were designing OpenCode itself.

Instead of treating project knowledge as a collection of markdown files, maintain a **typed graph of engineering knowledge** that is regenerated and synchronized every session.

For example:

```text
Project
│
├── Vision
│   ├── Design Pillars
│   ├── Constitution
│   └── Success Criteria
│
├── Architecture
│   ├── Modules
│   ├── Interfaces
│   ├── ADRs
│   └── Dependencies
│
├── Planning
│   ├── Roadmap
│   ├── Milestones
│   ├── Epics
│   ├── Issues
│   └── Tasks
│
├── Implementation
│   ├── Source Files
│   ├── Tests
│   ├── Benchmarks
│   └── Binary Budget
│
└── Operational Memory
    ├── Working Memory
    ├── Session Handoffs
    ├── Lessons Learned
    ├── Risks
    └── Open Questions
```

Every session begins by rebuilding this mental graph from the repository, then validating it against the current codebase. If a mismatch is detected—for example, `PROJECT_STATUS.md` claims the Ghost System is complete but the source tree doesn't contain it—the AI should flag the inconsistency before writing new code.

That transforms the coding agent from a **code generator** into a **stateful engineering teammate**. It doesn't merely remember what was said in a previous chat; it continuously reconciles **documentation, code, architecture, and project state** into a coherent model before taking action. That's the closest you can get today to giving an AI a persistent engineering memory.
