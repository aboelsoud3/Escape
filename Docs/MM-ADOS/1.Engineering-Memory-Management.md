# The biggest improvement I'd make

you are leading this project, you add one more document that most teams don't have:

## `project/WORKING_MEMORY.md`

Unlike a design document, this is a **rolling summary** of the project that is rewritten after every meaningful session. It should stay intentionally short—around one or two pages—and answer only the questions an engineer needs to resume work quickly:

* **What is the project trying to achieve right now?**
* **What was completed recently?**
* **What is currently in progress?**
* **What is blocked, and why?**
* **What assumptions are we making?**
* **What decisions changed recently?**
* **What should the next engineer (or AI session) do first?**

Every session starts by reading `WORKING_MEMORY.md` and ends by updating it. Think of it as the team's "RAM," while the rest of the documentation is the "hard drive."

## One step further: treat OpenCode as a real engineering organization

you are building **PULSE** today with OpenCode + Ollama, you would build a lightweight **AI Development Platform** inside the repository.

It would have four persistent layers:

```text
Repository
│
├── /docs            ← Stable knowledge (vision, GDD, TDD)
├── /project         ← Current state (working memory, sprint, status)
├── /tasks           ← Executable work (epics, issues, acceptance criteria)
└── /.agents         ← Agent definitions and workflows
```

For example:

```text
.agents/
├── architect.md
├── gameplay.md
├── renderer.md
├── reviewer.md
├── qa.md
├── producer.md
├── session_start.md
└── session_end.md
```

Each file defines a specialized role with responsibilities, inputs, outputs, and quality gates. Instead of relying on one giant prompt every session, OpenCode can load the appropriate agent definition based on the task at hand.

That architecture scales remarkably well because the **knowledge lives in version-controlled files**, not in ephemeral chat history. Months later—or even after switching models—you can resume development with minimal loss of context, which is exactly how professional engineering teams preserve continuity.
