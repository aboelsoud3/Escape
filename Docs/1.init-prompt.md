# EXPECTED OUTPUT

Produce a professional engineering planning package.

Do NOT produce code.

Do NOT implement features.

Do NOT skip reasoning.

Output should be suitable for a senior engineering team beginning implementation.

At the end of the planning package, produce a prioritized backlog for building the **Minimum Fun Prototype**, identifying the smallest sequence of tasks that results in a runnable prototype demonstrating the core gameplay loop.

This is only the **first** prompt in an agentic workflow.

In a production-grade setup with OpenCode, Claude Code, Codex CLI, or similar tools, I would not rely on one enormous prompt for the entire project. Instead, I would use a layered prompt architecture:

1. **System Prompt** – Defines the permanent engineering constitution (coding standards, design philosophy, contest constraints).
2. **Planning Prompt** – The document above, whose only job is to produce the execution roadmap.
3. **Epic Prompt** – Generates the implementation plan for a single epic (for example, Player Controller or Procedural Road).
4. **Issue Prompt** – Implements one GitHub issue at a time with strict acceptance criteria and allowed file scope.
5. **Review Prompt** – Performs architecture, performance, binary-size, and maintainability reviews before code is merged.

This separation mirrors how experienced engineering teams work: architecture first, implementation second, review third. It also produces much more reliable results from agentic coding tools because each agent has a clear, bounded responsibility rather than trying to solve the entire project in one step.
